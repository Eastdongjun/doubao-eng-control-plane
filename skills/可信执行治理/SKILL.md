# 可信执行治理

让豆包每一次"动手操作"都像受控的生产变更：**可预览、可审计、可回滚**。
核心原则：能力越强，越要管住手。不是限制能力，而是给每个动作装上护栏。

## 动作风险分级（先定级，再执行）

| 等级 | 含义 | 例子 | 执行策略 |
|---|---|---|---|
| L0 | 只读 | 读文件、搜索、查询、列表 | 直接执行 |
| L1 | 生成草稿 | 新建文件、写入新内容 | 直接执行 + 写审计 |
| L2 | 修改/执行 | 改已有文件、跑命令、构建 | 先备份 + diff 预览 + 执行 + 审计 |
| L3 | 外部动作 | 发消息、发布、上传、调用外部 API | 用户确认 + 完整审计 |
| L4 | 高风险 | 删除、覆盖、交易、批量、生产操作 | 必须用户确认 + 备份 + 回滚方案 |

## 执行协议（五步）

1. **识别**：判断动作对象（文件/命令/外部）与风险等级（L0-L4）。
2. **预览**：L2 及以上，先给出"将做什么"的可读说明：
   - 改文件 → 显示改动点（old → new）或 diff；
   - 跑命令 → 显示完整命令与工作目录；
   - 删除/覆盖 → 明示路径与影响范围。
3. **确认**：L3/L4 必须得到用户明确同意后才执行；L2 默认执行但记录。
4. **执行 + 审计**：执行动作，并把一条结构化记录追加到审计日志。
5. **回滚**：失败或用户要求时，从备份恢复，验证恢复后状态。

## 审计日志（每次操作必写）

- 位置：项目目录下 `.governance/audit.jsonl`（JSON Lines，逐行追加，不覆盖历史）。
- 每条记录字段：
  ```json
  {"ts":"2026-09-04T10:00:00+08:00","task":"任务标识","risk":"L2","action":"modify",
   "target":"文件路径","command":"执行的命令(如有)","backup":"备份路径","result":"ok|fail|rolled_back",
   "note":"说明"}
  ```
- 写前先确保目录存在；追加写入；中文内容 UTF-8。

## 备份与回滚

- **改文件前**：把原文件复制到 `.governance/backups/<时间戳>/<原名>`。
- **改文件后失败/异常**：用备份恢复原文件，验证内容一致后写 `result:"rolled_back"`。
- **删除前**：移动到 `.governance/trash/` 而非直接删，保留可恢复。
- **命令失败**：先读 stderr 定位，不回滚无关改动；确需回滚时按备份恢复。

## 与既有技能配合

- 自动开发闭环的写文件/跑命令 → `自动编码循环` 技能执行，本技能负责其中的"安全护栏"；
- 完整项目上线 → `工程化总控` + `上线就绪评审` 技能，本技能负责日常操作的可信执行；
- 事故处理 → `事故管理` 技能，本技能提供操作审计作为复盘依据。

## 硬性规则

- 所有 L2+ 动作必须留痕（审计日志），不留痕视为未执行。
- 改文件必先备份；删除不直接 rm，先进回收区。
- 高风险（L3/L4）动作未获确认不执行。
- 审计日志只追加、不覆盖、不删除（除非用户明确要求清理）。
- 回滚后必须验证恢复，不能只"恢复动作"不"验证结果"。
